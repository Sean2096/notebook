# AI 项目设计

## 设计结论

新版采用 **三个概念实验 + 一个贯穿式求职作品**。概念实验负责隔离变量、理解原理和记录失败；综合作品负责证明需求拆解、工程实现、效果评测和项目表达。

旧版四个 Demo 及其项目复盘卡已于 2026-10-22 删除，不作为新版代码基础。概念卡中的历史费曼记录保留，但其中对旧版实现的描述只代表当时学习过程。

所有实验按 [[AI 高效学习系统]] 执行：先闭卷预测，再运行对照，保留失败证据，最后进行费曼验收和延迟复测。AI 提供最小骨架、分级提示和审查，不代写核心逻辑。

## 目录结构

```text
demos/ai/
├── 01-llm-behavior-lab/
├── 02-rag-eval-lab/
├── 03-tool-agent-runtime/
└── 04-ai-support-workbench/
```

新工程在进入对应课程阶段时创建，不提前生成空骨架。项目复盘卡在完成里程碑并通过验收后创建：

```text
projects/ai/
├── 01 LLM Behavior Lab.md
├── 02 RAG Eval Lab.md
├── 03 Tool Agent Runtime.md
└── 04 AI Support Workbench.md
```

复盘卡的 `repo:` 和 `demo:` 必须使用完整路径，例如 `demos/ai/01-llm-behavior-lab`。

## 01 LLM Behavior Lab

**目标**：用最小实验回答“大语言模型在应用中怎样接收输入、生成输出，以及哪些约束由代码保证”。

实验范围：

- 消息角色、完整历史与无状态调用。
- Prompt（提示词）中的任务、约束、示例和资料。
- 上下文裁剪、摘要与信息丢失。
- 结构化输出与 Schema（数据结构约束）校验。
- 流式响应、错误和取消的实际边界。

建议结构：

```text
01-llm-behavior-lab/
├── src/
│   ├── cases/
│   ├── runners/
│   └── shared/
├── results/
└── README.md
```

每个实验包含：问题、控制变量、输入、原始输出、观察结果和结论。界面只服务于观察，不以视觉完整度作为主要验收项。

**通过标准**：

- 能复现“缺失历史”“格式合法但语义错误”“取消只影响部分链路”等失败。
- 能区分模型行为、SDK（Software Development Kit，软件开发工具包）行为和应用代码保证。
- 固定实验可重复执行，结果差异被记录而不是被隐藏。

## 02 RAG Eval Lab

**目标**：拆开评估检索与生成，理解 RAG（Retrieval-Augmented Generation，检索增强生成）每个环节的作用和失败模式。

实验范围：

- 文档解析、语义切分、重叠与来源元数据。
- 关键词检索基线。
- 真实 Embedding（嵌入向量）与精确向量搜索。
- 检索候选、上下文组装、引用和无依据拒答。
- BM25（Best Matching 25，关键词相关性排序算法）、RRF（Reciprocal Rank Fusion，倒数排名融合）和 Rerank（重排序）仅在基线暴露问题后加入。
- 检索命中、答案正确、引用支持和误拒分别评测。

建议结构：

```text
02-rag-eval-lab/
├── corpus/
├── eval/
│   ├── development_cases.json
│   └── holdout_cases.json
├── src/
│   ├── ingest.ts
│   ├── retrieve.ts
│   ├── answer.ts
│   └── evaluate.ts
├── results/
└── README.md
```

初期使用内存精确搜索，先看懂距离、排序和过滤。数据库与近似索引留给综合作品，避免基础设施掩盖检索原理。

**通过标准**：

- 调参集和保留集分开；查看保留集后不再称其为未见数据。
- 每次优化只改变一个主要变量，并保存前后结果。
- 能把错误归类为检索未命中、证据不完整、生成错误、引用不支持或错误拒答。
- 课程建议的小样本目标、口径和限制遵循 [[AI 零基础求职课程]]，不得包装为生产质量。

## 03 Tool Agent Runtime

**目标**：依次理解 Function Calling（函数调用）、固定工作流、Agent（智能体）循环与 MCP（Model Context Protocol，模型上下文协议），避免概念串线。

学习顺序：

1. 只读工具：定义、参数校验、执行结果和错误。
2. 写入工具：权限、操作预览、用户确认和幂等。
3. 固定工作流：由应用代码确定步骤。
4. Agent 循环：模型动态选择工具，设置步数、时间和调用预算。
5. MCP：将一个只读工具改由 MCP Server 提供，观察能力发现与传输边界。

建议结构：

```text
03-tool-agent-runtime/
├── src/
│   ├── tools/
│   ├── workflows/
│   ├── agent/
│   ├── mcp/
│   └── eval/
├── results/
└── README.md
```

写操作统一采用：

```text
模型提出操作 → 应用校验 → 展示预览 → 用户确认 → 执行 → 检查结果
```

**通过标准**：

- 覆盖正常执行、非法参数、无权限、超时、取消、未确认和重复确认。
- 不用模型最后一句“成功”判断工具成功，必须检查真实业务结果。
- 能解释工具调用、Agent、工作流和 MCP 各自的职责。
- 前端只展示可观测事件，不伪造模型隐藏思考过程。

## 04 AI Support Workbench

**目标**：作为唯一重点简历作品，证明可以把模型、检索、工具与前端交互组合成可验证的业务应用。

场景：企业知识与工单支持工作台。用户可以基于公开演示资料提问并定位引用，也可以读取演示工单、生成处理草稿，并在确认后执行写操作。

核心能力：

- 知识问答、结构化引用、无依据拒答。
- 工单读取、草稿生成、操作预览和人工确认。
- 任务状态、取消、错误恢复与重复提交控制。
- 用户、资料和工具权限。
- 请求轨迹、阶段耗时、模型使用量和评测结果。
- 固定回归数据集和失败案例记录。

默认技术栈：

- React + TypeScript + Vite。
- Node.js + Express。
- Vercel AI SDK 与 Zod。
- PostgreSQL + pgvector。
- MCP SDK，仅用于确有独立工具服务价值的能力。

不默认引入复杂 Agent 框架、多智能体、消息队列或独立观测平台。只有已有实现和测量结果证明需要时才增加依赖。

**求职验收**：

- 从干净环境可按说明启动，公开材料不包含密钥和私密数据。
- 正常流程、拒答、工具错误、无权限、取消和重复确认均有真实测试记录。
- 能用 30 秒说明场景和结果，用 3 分钟解释链路、取舍、数据和失败。
- 能在代码中定位本人实现，明确哪些能力尚未完成。
- 个人项目只按个人项目描述，不冒充企业生产经验。

## 统一工程规则

- 每个项目只解决声明范围内的问题，不复制整套聊天 UI。
- Eval（Evaluation，效果评测）和失败数据从第一天存在，不在项目末尾补造。
- 每个实验先写驱动问题、假设和预期结果，再运行代码。
- 调参数据和保留数据分开；正式验收前 AI 不读取保留集内容。
- 模型输出视为不可信外部输入；格式校验、权限和副作用由应用层保证。
- 所有 API、参数、版本和模型能力在实现当日核对官方文档及锁文件。
- 使用 TypeScript 明确类型；数据字段使用 `snake_case`，变量使用 `camelCase`。
- 助手只提供最小骨架和类型，核心实验及业务逻辑由学习者实现。

## 实施顺序

P0：按 [[AI 零基础求职课程]] 从 `01-llm-behavior-lab` 开始，先做起点诊断和第一个对照实验。

P1：每个实验达到验收线后再进入下一个项目，并创建对应项目复盘卡。

P2：三个实验完成后创建综合作品；混合检索、复杂 Agent、桌面端与 Python 分支由目标职位和实测问题决定。
