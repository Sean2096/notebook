# AI 零基础求职课程

## 学习目标与起点

**以 AI（Artificial Intelligence，人工智能）知识和应用实践从零开始设计，沿用已有 TypeScript、React、Node.js 基础。** 核心目标是解释大模型应用原理、实现关键链路、用证据判断效果，并能回答求职中的技术追问。

“AI 零基础”是课程起点假设，不等于没有软件工作经验，也不等于必须投实习或校招。岗位方向仍参考 [[AI 技术岗位调研]]：AI 应用前端、智能体产品工程，以及与实际后端能力匹配的大模型应用开发。投递级别由真实软件经验、身份与岗位要求决定。

默认 **12 周、24 次课，每周 8–10 小时，共 96–120 小时**：两次 90 分钟结对课、3–4 小时实践、2–3 小时复述和面试。课时是教学预算；掌握速度以验收为准。已有概念与练习先做诊断，通过即可跳过相应教学，不修改原有掌握记录。

课程只规定知识顺序和阶段目标；每节课统一按 [[AI 高效学习系统]] 的“闭卷诊断 → 定向补缺 → 最小实验 → 费曼验收 → 延迟复测”执行。已有知识通过诊断后直接进入实验或复测，不机械重复听课。

工程内容随 AI 任务出现，例如模型密钥、输出校验、取消和工具权限。项目边界、目录和验收统一参照 [[AI 项目设计]]。

## 术语与知识边界

以下术语随课程逐步理解，不要求先背词表。

- LLM（Large Language Model，大语言模型）：用于语言理解与生成的模型。
- Token（词元）：模型处理文本的基本单元，不等同于一个汉字或一个单词。
- Transformer（变换器架构）：本课程涉及的大语言模型常用架构；学习其输入、注意力和输出作用。
- Attention（注意力机制）：根据当前计算需要，对其他位置的信息进行加权利用的机制。
- Prompt（提示词）：提供给模型的任务描述、约束、示例和相关上下文。
- Embedding（嵌入向量）：将文本等内容编码成可比较的数值向量。
- RAG（Retrieval-Augmented Generation，检索增强生成）：先检索资料，再依据资料生成回答。
- BM25（Best Matching 25，关键词相关性排序算法）；RRF（Reciprocal Rank Fusion，倒数排名融合）：分别用于关键词排序与按名次融合结果。
- Rerank（重排序）；Cross-encoder（交叉编码器）：前者重新排序候选，后者联合读取问题与候选内容并打分。
- Schema（数据结构约束）：对字段、类型和合法值的约定。
- Function Calling（函数调用）：模型提出工具调用，由应用校验、授权和执行。
- Agent（智能体）：应用让模型根据任务选择行动，并结合工具结果继续执行的系统。
- MCP（Model Context Protocol，模型上下文协议）：应用与工具／资源服务交换上下文的协议。
- Eval（Evaluation，效果评测）：用明确任务、样本与标准检查应用表现。
- SSE（Server-Sent Events，服务器推送事件）：服务端持续向客户端推送事件的机制。
- TTFT（Time To First Token，首个词元延迟）：从事先约定的起点到首个模型输出词元的耗时。
- API（Application Programming Interface，应用程序接口）；SDK（Software Development Kit，软件开发工具包）。
- Fine-tuning（微调）：在已有模型基础上继续训练并修改其参数。
- Multimodal（多模态）：处理文本、图片、音频等不同形式的信息。

模型基础学到能解释应用行为：词元、生成机制、上下文、幻觉，以及预训练、微调和检索的区别。训练算法推导、训练框架源码和底层推理优化另设进阶路线。Python 按目标职位需要追加；主线用熟悉的 TypeScript 减少语言切换成本。

## 优先级

| 优先级 | 知识 | 求职价值 |
| --- | --- | --- |
| P0 立刻做 | LLM 心智模型、消息、提示词、上下文、输出校验 | 解释最基本的应用行为，避免把模型当确定性函数 |
| P0 主线必修 | Embedding、RAG、工具调用、Agent、MCP、评测 | 对应已调研应用岗位的核心能力，形成实践证据 |
| P1 近期 | 混合检索、精排、长任务恢复、成本与延迟、多模态边界 | 能对效果和工程取舍做进一步解释 |
| P2 进阶 | 复杂多智能体、微调实操、模型训练、推理优化 | 由岗位或真实任务需要决定，不挤占基础验收 |

## 12 周、24 次课

每课都回答三个问题：它解决什么问题？应用里的哪一步使用它？它会怎样失败？表中周次是建议节奏，不是强制进度；当前单元未通过复测时不增加新概念。费曼题只给题目，实际作答后再讲正确答案并存档。

| 周次 | A 课 | B 课 | 实验与费曼题 |
| --- | --- | --- | --- |
| 1 | **01 模型基础**：词元、Transformer、注意力、生成与训练的区别 | **02 对话基础**：消息角色、历史、上下文窗口、应用记忆 | 做遗漏历史／保留历史对照；“模型记忆和应用保存历史有什么区别？” |
| 2 | **03 提示词与幻觉**：任务、约束、示例、资料，事实与不确定性 | **04 结构化输出**：Schema、格式合法与语义正确、失败处理 | 同一批任务比较提示词；“结构正确为什么仍可能答错？” |
| 3 | **05 上下文工程**：信息选择、历史裁剪、摘要、预算 | **06 流式交互**：SSE、消息片段、工具事件、取消与错误 | 接入流式聊天并记录失败；“界面停止显示是否等于模型和工具都停止？” |
| 4 | **07 向量基础**：Embedding、维度、相似度、语义与关键词 | **08 检索基础**：切分、重叠、来源、元数据、离线索引 | 中文同义问题对照；“词袋向量为什么不能等同于真实语义向量？” |
| 5 | **09 RAG 主链路**：检索、上下文组装、生成、引用、拒答 | **10 RAG 评测**：检索命中、答案正确、引用支持、误拒 | 标注真实题集，先跑基线；“答案错误如何区分检索问题和生成问题？” |
| 6 | **11 检索优化**：BM25、向量、RRF，精排与代价 | **12 RAG 边界**：指代、文档更新、权限、RAG 与微调选择 | 同一题集做单因素对照；“加精排一定更好吗，如何证明？” |
| 7 | **13 工具调用**：工具定义、参数、执行结果、消息回传 | **14 工具边界**：校验、鉴权、超时、重试、确认与幂等 | 增加读取任务和生成草稿工具；“模型提出调用后，应用还必须做什么？” |
| 8 | **15 Agent 原理**：模型、工具、状态与执行循环 | **16 编排选择**：固定工作流、动态行动、停止条件、人工介入 | 对同一任务实现受限流程；“为什么不是每个业务都需要 Agent？” |
| 9 | **17 MCP 架构**：宿主、客户端、服务端，工具、资源和提示模板 | **18 MCP 集成**：能力发现、生命周期、传输、授权边界 | 接一个工具服务；“MCP、工具调用和 Agent 分别负责什么？” |
| 10 | **19 任务记忆与恢复**：会话历史、摘要、任务状态和可恢复性 | **20 质量与观测**：任务成功、失败轨迹、耗时、调用量、成本 | 重复执行、取消与重启实验；“保存历史为什么不等于完整恢复？” |
| 11 | **21 多模态与模型选择**：按任务评估能力、格式、延迟与成本 | **22 应用风险**：提示注入、不可信资料、工具权限、引用失真 | 用选定模型核实一种输入能力；“文档中的指令能否直接变成工具操作？” |
| 12 | **23 综合作品验收**：解释实际链路、测量结果与设计取舍 | **24 模拟面试与复习**：一题一答，追问后评分，修订薄弱概念 | 独立加一个小需求；“哪些能力已实现、哪些未实现，你用什么证据区分？” |

第 1–2 周就开始固定样本对照，不等到最终作品才评测。第 6 周用小规模检索实验理解方法，不要求同时引入多个数据库或框架。第 11 周的模型能力以选定模型当前文档和实测为准，不默认所有模型接受同样输入。

## 实践安排

旧版练习已清空，新项目按课程阶段从零创建，不提前生成空骨架。

| 实践载体 | 对应课程 | 重点补的证据 |
| --- | --- | --- |
| `demos/ai/01-llm-behavior-lab` | 第 1–3 周 | 历史、上下文、结构化输出和流式取消的实际行为 |
| `demos/ai/02-rag-eval-lab` | 第 4–6 周 | 真实语义检索、中文问题、引用、拒答、优化前后结果 |
| `demos/ai/03-tool-agent-runtime` | 第 7–10 周 | 工具、工作流、Agent 与 MCP 的职责及失败轨迹 |
| `demos/ai/04-ai-support-workbench` | 第 11–12 周及后续 | 将已验收能力整合为可演示、可评测的求职作品 |

最终把所学能力组织成“AI Support Workbench”：基于公开文档问答并定位引用，读取演示任务，生成草稿，用户确认后保存。求职作品优先做到一条完整流程可解释、可测量，范围遵循 [[AI 项目设计]]。

新实现由学习者写核心逻辑，助手提供最小骨架和类型。新增工程时使用实际空闲编号，不覆盖已有练习。项目里程碑完成后更新对应复盘，`repo:` 和 `demo:` 写完整工程路径。

## 验收与面试证据

每课通过需满足四项：用自己的话解释；指出它在代码中的位置；复现一个失败情况；解释方案的代价或边界。会背定义、只会在骨架中填空、把计划功能说成已经实现，都不能直接算通过。

第 3、6、9、12 周集中复测。前三次分别检查模型应用基础、RAG、工具／Agent／MCP；最后一次检查综合作品和面试表达。允许查 API 文档，核心逻辑须能够独立解释和修改。

问答练习建议用 30 道调参题及另外 20 道保留题，来自真实公开资料；保留题含 10 道可答和 10 道不可答。分别保存检索候选、答案、引用、拒答及运行配置。调参后的结果不能仍被称为未见数据。

课程目标可设为：保留集可答题至少 8/10 在前五候选中找到相关片段，不可答题至少 8/10 正确拒答；另报告误拒、答案正确性和多片段证据完整性。这是小样本教学目标，不是招聘或生产质量标准。

工具任务覆盖正常执行、非法参数、无权限、超时、取消、未确认与重复确认，检查实际业务结果。没有确认的写入不得发生，重复确认不产生重复业务结果；这组测试不等于完整安全证明。

模拟面试每次只出一题，等作答后再追问、评分和给参考答案。评分看正确性、职责边界、设计取舍和实践证据；未掌握点回到概念卡修订。求职保留原有前端工程经验，重点增加可证实的 AI 能力，不把个人项目包装成生产经历。

## 第一课起点

第一题：**“聊天页面每次请求只发最新一句话，用户问‘那刚才那个呢’，你预计会发生什么？为什么？”**

先凭直觉回答，再做保留历史与遗漏历史的最小对照。已有概念卡若能闭卷讲清并接住追问，可跳过该课的基础讲解，进入边界实验。
